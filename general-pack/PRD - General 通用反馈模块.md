# PRD · General 通用反馈模块

> ATOM / 型动公园 — App 内通用问题反馈入口
> 版本 v1.1 · 状态：交互与文案定稿 · 平台 iOS / Android / HarmonyOS · 语言 7 种（zh en ja es pt de fr）

---

## 0. 一句话与愿景

把"我"页里旧版 *Bug Report* 升级为一个 **低阻力、可分流、可闭环** 的通用反馈入口：一级列表选类型 → 底部抽屉填内容 → 一次提交，后端按类型路由到既有处理链路。填完即走，不打断使用。

**核心愿景 —— 产品与用户之间的信息闭环：**

```
用户反馈  →  自动分类 / 路由 / 归并  →  产品&研发处理  →  结果回执给用户  →  用户感知"被听见"  →  更愿意反馈
   ↑                                                                                    │
   └──────────────────────────── 正反馈循环 ────────────────────────────────────────────┘
```

本期先打通"进"（收集 + 路由 + 归并）；下一步补"回"（状态回执、"你反馈的问题已修复/已采纳"通知），形成闭环。埋点从第一天就要能支撑闭环度量（见 §7）。

---

## 1. 目标与非目标

**目标**
- 降低反馈门槛：抽屉式、单步、可只选不填、可语音。
- 收上来的是**有效信息**：分类清晰、避免空提交。
- 复用既有链路：AI 识别 / 课程内容直接进现有看板与 bug bot，不新开通道。
- 可全球化：一套 UI，7 语言文案，跟随系统语言。
- 为闭环打底：结构化数据 + 埋点，支撑后续"回执"。

**非目标（本期）**
- 不做工单系统 / 客服会话（复杂问题引导到企业微信或邮箱）。
- 不做页面级语言 / 版本切换（真机跟随系统与账号地区）。
- 不做反馈历史列表与状态追踪 UI（闭环"回"的部分，下一期）。
- 不做"新增动作申请"独立流程（本期折叠，见 §3 备注）。

## 2. 信息架构

```
一级 · App View（问题反馈页）
  分类列表（5 类） + 售后直达（客服邮箱 / 企业微信）
        │ 点任一分类
        ▼
二级 · 底部抽屉（Bottom Sheet）
  子项多选 → 补充说明（打字 / 语音）→ 截图（折叠）→ 联系方式（成组）→ 提交
        │ 提交
        ▼
抽屉内 · 感谢 + 满意度（😍🙂😕，选填）→ 完成关闭
```

交互范式与"AI 计划结果吐槽"一致：底部抽屉、grab handle、遮罩、缓动上滑、下滑关闭。用户全程感知"这里很简单，填一填就走"，**不做整页二级跳转**。

## 3. 分类与选项（MECE）

| 一级分类 | 子项（多选，选填） | 路由去向 |
|---|---|---|
| **AI 识别准确性** ·（复用课中链路） | 计数多了（没做也计）· 计数少了（做了没计）· 身体识别不准 · AI 讲解不清楚 | AI bug bot / 算法看板 |
| **课程内容** ·（复用课中链路） | 示范图 / 视频不对 · 动作名称不对 · 训练部位标注不对 · 动作讲解不对 | 课程内容看板 |
| **连接数据与使用体验** | 设备连不上 / 老掉线 · 数据丢失或不同步 · 卡顿、闪退或不流畅 | Bug 看板（设备 / 数据 / 性能 标签） |
| **其他问题** | 无子项，自由文字 / 语音 | Bug 看板（待人工归类） |
| **新功能建议** | 无子项，自由文字 / 语音 | 产品需求池（**不进 bug 看板**） |

- 「AI 识别准确性」「课程内容」的选项与"课中报错"入口 **逐条一致**，工程侧复用同一套 `targetType` / 归并键 / 路由，无需另建。
- **备注（新增动作申请）**：本期不做独立入口；用户想要的动作走「课程内容」或「其他问题」的自由文字提出，后端可按关键词打标进教练审核队列。若后续要独立表单，再单开二级页。

## 4. 关键交互

### 4.1 提交前校验（防空提交）
- **有选项的分类**（AI / 课程内容 / 连接）：未勾选任何子项 **且** 无补充文字 / 语音 → 提交按钮**置灰不可点**；勾一项、或打字、或录一段语音即可提交。
- **纯文字分类**（其他问题 / 新功能建议）：必须有文字或语音才能提交。
- **防重复**：点击提交后立即置灰按钮，避免连点重复提交（配合后端 `idempotencyKey`）。

### 4.2 截图（折叠，降心理阻力）
默认只是一行"截图〔选填〕" + 右侧一个 `+`；点 `+` 才展开占位图片框并加入首张；删到空时自动收回成一行。避免表单里始终留一个空的加号框。最多 3 张。

### 4.3 联系方式（成组 · 弱化）
- 整组收进一张 **浅灰分组卡片**（iOS grouped-list 观感），字号偏小，视觉退到次要，不与"补充说明"抢注意力。
- **国际版**：默认填充账号**邮箱**（"回复会发到这里"），可"换一个"改用备用邮箱。
- **大陆版**：默认填充账号**手机号**（可"换一个"），并引导补充一个联系**邮箱**；不填微信号，但引导加**企业微信客服**。
- 卡片底部一条默认勾选：**「有需要才找你，平时不打扰」**—— 一般不回复，仅当问题复杂、需补充信息时才通过留下的联系方式找用户。

### 4.4 补充说明 / 语音
文字上限 200 字（带计数）；可点麦克风**录音（≤60 秒）**，存音频即可，是否 ASR 转写由后端决定。录音条可取消 / 删除，删除后恢复可提交态判断。

### 4.5 感谢 + 满意度
提交后抽屉切到感谢页：文案随分类不同（普通 / 建议）；下方 😍🙂😕 满意度选填，一点即走。

## 5. 多语言

7 种：`zh` 简体中文 · `en` English · `ja` 日本語 · `es` Español · `pt` Português(BR) · `de` Deutsch · `fr` Français。
- 真机 **跟随系统语言**；原型 / 文档里的语言开关仅供评审对照。
- 文案源：`i18n.json`（机器读，可转 ARB） + `i18n - 多语言文案对照.md`（人读对照表）。
- 语言与版本（大陆 / 国际）**正交**：版本决定联系方式形态与售后渠道，语言只切文案。
- 海外语言（es/pt/de/fr）涉及 GDPR，联系方式属 PII，需加密存储、可删除、仅在 `contactConsent=true` 时用于回访。

## 6. 后端与数据

### 6.1 提交 payload（建议）
| 字段 | 说明 |
|---|---|
| `category` | ai / content / connect / otherfb / feature |
| `subtypeIndex[]` | 勾选的子项下标（有选项分类） |
| `text` | 补充说明（≤200） |
| `voiceId` | 录音文件 id（先本地存，异步上传） |
| `shots[]` | 截图 id（≤3） |
| `contact` | { type: email/phone, value, altEmail? } |
| `contactConsent` | bool（默认 true，可取消） |
| `lang / region` | 系统语言 / 账号地区 |
| `meta` | 设备型号、App 版本、OS —— 静默附带，页面不再展示说明 |
| `idempotencyKey` | 去重用，先存后传 |

### 6.2 路由与归并
- 按 `category` 路由（见 §3 表）；**新功能建议**单独进产品需求池。
- AI / 课程内容复用课中既有 `targetType`，与课中反馈 **同源归并**（按 targetId + user 去重合并热度）。
- **先本地队列后异步上传**（无网也能提交），带 `idempotencyKey` 防重；失败指数退避重试。
- **限流**防刷（同一 user 提交频率上限）。

## 7. 埋点（为闭环打底）

| 事件 | 关键属性 |
|---|---|
| `feedback_entry_view` | source（入口来源） |
| `feedback_category_tap` | category |
| `feedback_submit` | category, subtypeCount, hasText, hasVoice, shotCount, consent, lang, region |
| `feedback_submit_fail` | reason（offline / server） |
| `feedback_satisfaction` | face（😍🙂😕） |
| `feedback_resolved_notified`（下一期·闭环回） | category, daysToResolve |

度量北极星：**反馈→处理→回执** 的闭环率与时长；分类分布；提交完成率（进入抽屉 vs 提交）。

## 8. 边界与状态检查（空 / 极限 / 边界）

| 场景 | 期望 |
|---|---|
| **空 · 账号无邮箱 / 手机号** | 不展示预填卡，改展示可输入的邮箱 / 手机号输入框（选填） |
| **空 · 无网提交** | 本地排队，提示"已保存，联网后自动提交"，不阻断 |
| **空 · 未选未填** | 提交置灰（见 §4.1） |
| **极限 · 文字 200 字满** | 计数变色 / 停止输入，不报错 |
| **极限 · 录音 60 秒** | 自动停止并生成语音条 |
| **极限 · 截图 3 张** | `+` 不再新增 |
| **极限 · 超长分类名（DE/FR）** | 两行换行不截断；超长邮箱省略号 |
| **边界 · 只勾选 / 只文字 / 只语音** | 任一即可提交 |
| **边界 · 提交中断网** | 转本地队列，按钮态正确恢复 |
| **边界 · 连点提交** | 首点即置灰，不重复提交 |
| **边界 · 切语言 / 版本后** | 已勾选、已填内容保留 |
| **边界 · 键盘弹出** | 抽屉随 viewInsets 避让，输入框不被遮挡 |
| **可访问性** | 勾选 / 按钮点区 ≥44pt；VoiceOver / TalkBack 有标签；对比度达标 |

## 9. 多角色评审（后端 / 测试 / 交互）

### 9.1 资深后端工程师
- ✅ **幂等 + 去重**：`idempotencyKey`；同 user+category+内容短时窗去重。
- ✅ **先存后传**：本地队列（Hive）+ 异步上传（Dio），离线可提交，失败退避重试。
- ✅ **归并**：与课中同源，按 targetType 合并热度，避免重复工单。
- ✅ **附件**：录音 / 截图先本地，签名 URL 异步上传；限时长 / 大小。
- ⚠️ **隐私 / 合规**：contact 属 PII，海外走 GDPR —— 加密存储、可删除、仅 consent=true 时用于回访；`meta` 不含精确位置。
- ⚠️ **限流防刷**：同一 user 频率上限 + 服务端校验必填。
- 🔭 **闭环预留**：提交返回 `feedbackId`，为后续"回执"建立可寻址主键。

### 9.2 测试工程师
- 覆盖 §8 全部空 / 极限 / 边界用例；重点：**空账号回退输入框**、**离线队列**、**连点防重**、**切语言保留输入**、**DE/FR 长文换行**。
- 多语言：无 RTL 语言（不涉阿拉伯 / 希伯来），但需验德 / 法长词换行与字体缺字回退。
- 兼容性矩阵：iOS / Android / HarmonyOS × 大陆 / 国际 × 7 语言（抽样）。
- 回归：AI / 课程内容子项与"课中报错"逐条一致（同源）。

### 9.3 交互设计师
- ✅ 抽屉键盘避让、grab handle + 下滑关闭、遮罩点击关闭。
- ✅ 截图折叠降阻力；联系方式弱化分组；感谢 + 满意度不强制。
- ✅ 语言 / 版本正交，真机自动，不给用户切换负担。
- ⚠️ **置灰提交需可解释**：可选加一句极浅提示（如按钮上方 "选一项或写一句即可提交"），或首次点击置灰按钮时轻震动 / 轻提示。当前保持纯净置灰，二选一由团队定。
- ⚠️ **首屏**：5 类是否都常用？可按数据把低频类折叠进"其他"，保持列表短。

> 本轮已落地：提交防重复置灰、空账号回退输入框（Flutter）、长文换行、键盘避让、区域开关前置、移除独立"新增动作申请"。

## 10. 技术实现方案：Flutter vs H5（含鸿蒙无缝嵌入）

诉求：**无缝嵌入 iOS / Android / HarmonyOS**。关键变量是鸿蒙 —— HarmonyOS NEXT（纯血鸿蒙）已移除 AOSP，**Android APK 不再能跑**，需 ArkTS/原生或适配层。

| 维度 | Flutter | **H5（WebView 嵌入）** |
|---|---|---|
| iOS / Android | 成熟，接近原生体验 | 成熟（WKWebView / Android WebView） |
| **HarmonyOS NEXT** | 社区 / 华为 fork（Flutter for OpenHarmony）尚不稳定，需额外适配 | **原生 ArkWeb 组件直接承载**，三端统一 |
| 一处改动三端生效 | 需各端打包 | **一份 H5，三端 WebView 即时更新** |
| 与宿主 App 的账号 / 权限打通 | 原生直接可用 | 需 **JS Bridge**（注入 email/phone/region/lang，调起相册 / 麦克风） |
| 录音 / 截图 | record / image_picker | Web 录音（MediaRecorder）或桥接原生；截图走系统选择器（桥接） |
| 发版灵活性 | 跟随 App 发版 | **可热更**（服务端改文案 / 分类不发版） |
| 体验一致性 | 最佳 | 好，需控字体 / 滚动 / 键盘细节 |

**建议**：这是一个**自包含的表单模块**、且要覆盖鸿蒙 —— 采用 **H5 + 各端 WebView（iOS WKWebView / Android WebView / HarmonyOS ArkWeb）+ 轻量 JS Bridge** 最"无缝"：一份代码三端跑、可热更文案 / 分类、鸿蒙无需等 Flutter 生态成熟。本包内的 `UX-Demo …html` 本身就是可直接演进为生产的 H5 基座。

- **JS Bridge 契约**（宿主注入 / 回调）：
  - 注入：`{ userEmail, userPhone(脱敏), region, lang, appVersion, os, deviceModel }`
  - 调用宿主：`pickImages(max)`、`recordAudio(maxSec)`、`submitFeedback(payload)`、`close()`
- **Flutter 作为备选**：若团队坚持 Flutter 且可接受鸿蒙用 OpenHarmony fork 或后置支持，本包 `flutter/` 提供等价实现（同一 i18n / 校验 / 交互），iOS + Android 可先上，鸿蒙用 H5 兜底。

> 结论：**优先 H5 模块**（三端无缝 + 热更），Flutter 版作为 iOS/Android 的原生备选。两版共用 `i18n.json` 与本 PRD 的校验 / 路由契约。

## 11. 验收标准（节选）

1. 5 分类、各子项文案与 §3 一致；AI / 课程内容与课中入口逐条一致。
2. 提交校验：空态置灰，勾选 / 文字 / 语音任一即可；连点不重复。
3. 截图默认折叠一行，点 + 展开，删空收回。
4. 联系方式成组浅灰卡片；国际=邮箱预填、大陆=手机号预填+补充邮箱+企微；许可默认勾选可取消；**空账号回退输入框**。
5. 7 语言均无缺字、无截断；跟随系统语言。
6. 提交后感谢文案随分类正确；满意度可选可跳过。
7. §8 边界用例全过。
