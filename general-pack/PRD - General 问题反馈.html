General 问题反馈 · PRD

ATOM / 型动公园 — App 内通用问题反馈入口

版本 v1.0  ·  状态 交互与文案定稿  ·  平台 iOS / Android（Flutter）  ·  语言 7 种（zh / en / ja / es / pt / de / fr）

0一句话

把"我"页里旧版 Bug Report 升级为一个低阻力、可分流的通用反馈入口：一级列表选类型 → 底部抽屉填内容 → 一次提交，后端按类型路由到既有处理链路。填完即走，不打断使用。

1目标与非目标

目标

  • 降低反馈门槛：抽屉式、单步、可只选不填、可语音。
  • 收上来的是有效信息：分类清晰、避免空提交。
  • 复用既有链路：AI 识别 / 课程内容直接进现有看板与 bug bot，不新开通道。
  • 可全球化：一套 UI，7 语言文案，跟随系统语言。

非目标

  • 不做工单系统 / 客服会话（复杂问题引导到企业微信或邮箱）。
  • 不做页面级语言/版本切换（真机跟随系统与账号地区）。
  • 不在本期做反馈历史列表与状态追踪。

2信息架构

一级 · App View（问题反馈页）
分类列表（5 类）＋ 售后直达（客服邮箱 / 企业微信）
  ↓ 点任一分类
二级 · 底部抽屉（Bottom Sheet）：子项多选 → 补充说明（打字 / 语音）→ 截图（折叠）→ 联系方式（成组）→ 提交
  ↓ 提交
抽屉内 · 感谢 + 满意度（😍🙂😕，选填）→ 完成关闭

「新增动作申请」是 课程内容 分类抽屉内的二级入口，点入后在同一抽屉切换到申请表单，「返回」回到分类表单。其余分类不出现该入口。

交互范式与"AI 计划结果吐槽"一致：底部抽屉、grab handle、遮罩、缓动上滑。用户全程感知"这里很简单，填一填就走"，不做整页二级跳转。

4关键交互

4.1 提交前校验（防空提交）

  • 有选项的分类（AI / 课程内容 / 连接）：未勾选任何子项 且 无补充文字 / 语音时，提交按钮置灰不可点；勾一项、或打字、或录一段语音即可提交。
  • 纯文字分类（其他问题 / 新功能建议）：必须有文字或语音才能提交。
  • 「新增动作申请」：动作名称必填，其余选填。

4.2 截图（折叠，降心理阻力）

默认只是一行"截图 选填"＋右侧一个 +；点 + 才展开占位图片框并加入首张；删到空时自动收回成一行。避免表单里始终留一个空的加号框。最多 3 张。

4.3 联系方式（成组 · 弱化）

  • 整组收进一张浅灰分组卡片（iOS grouped-list 观感），字号偏小，视觉退到次要，不与"补充说明"抢注意力。
  • 国际版：默认填充账号邮箱（"回复会发到这里"），可"换一个"改用备用邮箱。
  • 大陆版：默认填充账号手机号（可"换一个"），并引导补充一个联系邮箱；不填微信号，但引导加企业微信客服。
  • 卡片底部一条默认勾选：「有需要才找你，平时不打扰」—— 一般不回复，仅当问题复杂、需补充信息时才通过留下的联系方式找用户。

4.4 补充说明 / 语音

文字上限 200 字；可点麦克风录音（≤60 秒），存音频即可，是否 ASR 转写由后端决定。录音条可取消 / 删除，删除后恢复可提交态判断。

4.5 感谢 + 满意度

提交后抽屉切到感谢页：文案随分类（普通 / 申请 / 建议）不同；下方 😍🙂😕 满意度选填，一点即走。

5多语言

共 7 种语言：zh 简体中文 · en English · ja 日本語 · es Español · pt Português (BR) · de Deutsch · fr Français。

  • 真机跟随系统语言；原型内的语言开关仅供预览对照。
  • 文案源见附件 i18n.json 与 i18n - 多语言文案对照.md，可直接生成 ARB / i18n 资源。
  • 语言与版本（大陆 / 国际）正交：版本决定联系方式形态（手机号+企微 / 邮箱）与售后渠道展示，语言只切文案。

6后端与数据

6.1 提交 payload（建议）

字段说明
categoryai / content / connect / otherfb / feature
subtypes[]勾选的子项 key（有选项分类）
text补充说明（≤200）
voiceId录音文件 id（先本地存，异步上传）
shots[]截图 id（≤3）
contact{ type: email/phone, value, altEmail? }
contactConsentbool（默认 true，可取消）
lang / region系统语言 / 账号地区
meta设备型号、App 版本、OS —— 静默附带，页面不再展示说明
idempotencyKey去重用，先存后传

6.2 路由与归并

  • 按 category 路由（见 §3 表）；新功能建议单独进产品需求池。
  • AI / 课程内容复用课中既有 targetType，与课中反馈同源归并（按 targetId + user 去重合并热度）。
  • 先本地队列后异步上传（无网也能提交），带 idempotencyKey 防重。

7验收标准（节选）

  1. 5 分类、各子项文案与本 PRD §3 完全一致；AI / 课程内容与课中入口逐条一致。
  2. 提交校验：空态置灰，勾选 / 文字 / 语音任一即可提交。
  3. 截图默认折叠一行，点 + 展开，删空收回。
  4. 联系方式成组浅灰卡片；国际=邮箱预填、大陆=手机号预填+补充邮箱+企微；许可默认勾选可取消。
  5. 7 语言均无缺字、无截断；跟随系统语言。
  6. 提交后感谢文案随分类正确；满意度可选可跳过。
